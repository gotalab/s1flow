# 接続ファイルとその探し方

接続ファイルは、アプリが呼び出してよいモデルの一覧です。このページでは、どのファイルが信頼されるかと、SDK と CLI がそのファイルをどう見つけるかを説明します。

## 接続ファイル { #the-connection-file }

TOML の形式では、モデルごとに `[models.NAME]` セクションを一つ書きます（[アプリで判断を動かす](app.md#your-first-decision)の例を参照）。中身はプロジェクトの `s1flow.toml` からコピーします。`default`（`--models` を付けないときに `s1flow run` と `doctor` が使うモデル）は任意なので、アプリのファイルでは省けます。接続は、アプリが実装した独自のプロバイダーを指すこともできます。

渡したファイルに書いたモデルが、そのまま呼び出してよいモデルのすべてになります。そのため本番には、関係のない認証情報が並ぶ研究用のカタログではなく、専用のファイルを用意してください。ポリシーが、プロバイダーの import、エンドポイントの URL、認証情報の名前や値を持ち込むことはできません。s1flow がプロジェクトのカタログをアプリのファイルに混ぜることもありません。

## SDK { #the-sdk }

`Client()` と `AsyncClient()` は、プロジェクトや設定ファイル、`.env`、組み込みのカタログを探しません。ただし、設定したモデルが必要とするときは、プロバイダーが自分の API キーの環境変数を読みます。

直接の呼び出しで `"triage"` のような別名でモデルを指すときは、`connections=` を渡します。直接渡した `ModelSpec` や `DecisionModel` はすでに明示的なので、接続ファイルは要りません。接続は `client.connections` で参照できます。

`connections`、キャッシュ、ログの相対パスは、クライアントやポリシーを作ったときの作業ディレクトリを基準に解決します。SDK が dotenv ファイルを読むことはありません。`policies.load` には、明示的な `path=` か `root=` が要ります。今のプロジェクトからポリシーを探すことはなく、明示したポリシーのパスは `load` を呼んだときに解決します。

`cache_dir` は任意で、`Client` と `AsyncClient` でだけ使われます。プロバイダーは、価格表のような補助的なデータにこのディレクトリを使います。s1flow が、実行時にモデルの答えを使い回すためにこれを使うことはありません。評価には専用の答えのキャッシュがあります。接続ファイルを読み込んだだけでは、プロバイダーは作られません。プロバイダーを作ったり確かめたりするには、`client.connections.build()` か `.check()` を使います。

## CLI { #the-cli }

コマンドが `--project PATH` と `--connections PATH` を取るかどうかは、`s1flow COMMAND --help` に出ます。

`--project` には、`s1flow.toml` を含むディレクトリか、`s1flow/s1flow.toml` を含むリポジトリを直接指していなければなりません。上の階層を探すことはありません。`--project` が無ければ、CLI は今のディレクトリから一番近い Git のルートまで上に向かって探します。Git リポジトリの外では、今のディレクトリと `./s1flow` だけを確かめるので、もっと深い場所から実行するときは `--project` を使ってください。

評価のコマンドは、`--connections` があればそれを使い、無ければ選んだプロジェクトの `s1flow.toml` を使います。`decide --policy`、`doctor --policy`、`adopt --spec --root` には明示的な `--connections` が要ります。`feedback record` はモデルを呼ばないので、`--connections` を取りません。

CLI は、プロジェクトのディレクトリ（プロジェクトが無ければ今のディレクトリ）と、そこから Git のルートまでの各親ディレクトリにある `.env` を、近い順に読みます。すでに設定されている変数が優先されます。プロジェクトが見つからないときは、どこから探し始め、どこを見たかをエラーで伝え、`--project PATH` か `--connections PATH` を勧めます。
